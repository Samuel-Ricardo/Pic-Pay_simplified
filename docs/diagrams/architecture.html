3 · C4 — Component (L3) — Layered / Pseudo-Hexagonal

Intent: domain (entities/DTOs/ports) ← application (use-cases/policies/services) ← infra (config/middleware/gateway). Reality: upward leak NotRequireAuthInWhiteListPolicyImpl → infra.config.security.SecurityConfig.WHITE_LIST. Field injection dominates.

4 · Sequence — Authentication (Login → JWT 2h)

POST /auth/login {email,password} → AuthenticationController → AuthenticateUserUseCase → DaoAuthenticationProvider (BCrypt) → GenerateJWTUseCase (HMAC256, exp 2h via TokenMustExpiresInTwoHoursPolicyImpl) → response {token}. Subsequent requests: JWTAuthMiddleware OncePerRequestFilter validates header → SaveAuthContextUseCase.

5 · Sequence — Transaction (Transfer + Notification)

POST /transactions {value,senderId,receiverId} requires EXECUTE_TRANSACTION. Flow: find sender → validate() (merchant + balance + authorizer) → find receiver → TransactionUseCase.execute() (subtract/add) → SaveTransactionUseCase + update balances → SendNotificationOnTransactPolicy → HttpGateway.post(). Missing @Transactional → partial commit risk; no idempotency → double-spend.

6 · ERD — Data Model (JPA / PostgreSQL)

tb_users (UUID id, unique email/document, balance BigDecimal, enum string userType, enums ordinal bug role) 1—N tb_transactions (AUTO UUID id, amount, sender_id FK → users, receiver_id FK → users, createdAt). No migrations; ddl-auto=update in prod.

7 · Request Lifecycle & Policy Chain

Filter JWTAuthMiddleware → SecurityFilterChain.authorizeHttpRequests (WHITELIST 9 paths + RBAC) → Controller @Valid → Service validate() (policy chain: Merchant → Balance → Authorizer) → UseCase → Persistence → Notification. Policies are Strategy via interfaces.
